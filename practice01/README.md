# ПР-01 · Каталог товаров: витрина и правки

Практическая работа справочника по MongoDB, после модуля 1:
https://maximbytecamp.github.io/mongodb_theory_makarov/praktiki/01-katalog-tovarov/

Решение на Python — [`solution.py`](solution.py). Базы: `shop` читаем,
`sandbox` меняем.

## Что сделано

**Задача 1 · витрина каталога.** Функция
`catalog_page(category=None, page=1, per_page=5, sort_field="price", desc=True)`
возвращает `(items, total)`. Фильтр по категории собирается по условию,
в проекцию идут только `sku`, `title`, `price`, `rating` без `_id`, сортировка
по двум ключам (`sort_field` + `sku`), страницы через `skip`/`limit`,
`total` считает сервер через `count_documents` с тем же фильтром.
Страница за пределами данных возвращает пустой список, а не ошибку.

**Задача 2 · приёмка поставки.** Четыре шага в `sandbox` с отчётом:
остатки трёх артикулов через `$inc` с проверкой `matched_count`, две новинки
через `insert_many(ordered=False)` с явными `_id`, снятие `SKU-CP-018` по схеме
«посчитать → показать → удалить», бесплатная доставка аксессуарам одним
`update_many`. Числа в отчёте берутся из результатов операций.

## Как запустить

Стенд — `stend/` этого репозитория, данные для практики — из учебного
репозитория курса. Клонируются рядом, один раз:

```bash
git clone https://github.com/MaximBytecamp/mongodb-practice.git
```

Дальше из корня своего репозитория:

```bash
docker compose -f stend/docker-compose.yml up -d       # сервер на 27017
bash ../mongodb-practice/stend/load.sh                 # чистые данные

cd practice01 && python3 solution.py                   # pip install pymongo
python3 ../../mongodb-practice/practice01/check.py     # самопроверка
```

Полный сброс стенда — `docker compose -f stend/docker-compose.yml down -v`.
Другой адрес сервера задаётся переменной `MONGO_URI`, её понимают и решение,
и проверка.

## Ответы на вопросы приёмки

**Почему сортировка по двум ключам.** `sort` по одной цене не задаёт порядок
внутри группы товаров с равной ценой: сервер волен вернуть их как угодно, и от
запроса к запросу порядок меняется. При постраничной выдаче это значит, что
товар попадает и на страницу 1, и на страницу 2, а другой не попадает никуда.
Второй ключ `sku` уникален, поэтому порядок становится однозначным.

**Что вернёт функция для девятой страницы.** `([], 5)` — пустой список и
прежний `total`. `skip` за пределами выборки — не ошибка: курсор просто пуст.
`total` считается отдельным `count_documents` с тем же фильтром, поэтому от
номера страницы не зависит, и фронт по-прежнему рисует «9 из 2».

**Почему остатки меняются через `$inc`.** `$inc` прибавляет на сервере, атомарно
в рамках документа. Чтение-в-Python-запись создаёт гонку: две приёмки читают
остаток 10, каждая прибавляет своё и пишет 15 — при приходе 5 и 5 вместо 20 в
базе остаётся 15, и ни одна операция не сообщит об ошибке. Заодно `$inc`
создаёт поле `qty_total`, если его ещё нет.

**Что произойдёт при повторном запуске.** Новинки не задвоятся: `_id` задан
явно (`p-101`, `p-102`), вторая вставка упирается в `E11000`, `ordered=False`
даёт вставить всё остальное, а в отчёт идёт 0 новых позиций. Удаление и
`update_many` идемпотентны — `deleted_count` и `modified_count` станут 0, в
каталоге по-прежнему 22 позиции. Не идемпотентен только `$inc`: он прибавит
остатки второй раз, поэтому приёмку запускают на чистых данных.
